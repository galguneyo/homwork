# HCM Release Radar

Workday HCM과 SAP SuccessFactors의 **반기 릴리스를 추적·비교하는 나만의 에이전트**와, 그 첫 실행 산출물.

## 왜 에이전트인가

두 벤더는 모두 연 2회 릴리스하지만 **분기가 어긋나고, 문서 공개 정책이 반대이며, 패키징 논리도 반대**입니다. 반기마다 이 구조를 처음부터 재구성하면 비싼 작업(판단)이 싼 작업(수집)에 묻힙니다. 이 레포는 수집 절차·증거 규율·대칭 프레임을 고정해 두고, 매 반기 판단에만 집중하기 위한 것입니다.

      output-template.md                   # 산출물 템플릿 (9개 섹션)

```

```

## 설계 원칙

이 에이전트는 **제안서에 들어갈 사실을 만듭니다.** 따라서 기능을 하나 빠뜨리는 것보다 **없는 기능을 하나 지어내는 것이 치명적**입니다. 세 가지 규율로 이를 강제합니다.

1. **티어 태깅** — 모든 사실 라인에 출처 티어(T1 벤더 / T2 파트너 / T3 미디어)와 URL. 날짜는 T1 또는 독립 T2 2건 일치일 때만 단정.
2. **Tier-1-or-silence** — 근거가 없으면 벤더 마케팅 문구로 칸을 채우지 않고 `문서 비공개 / 미확인`으로 둡니다.
3. **비대칭 규칙** — Workday는 릴리스 노트가 로그인 게이트, SAP는 공개. **공개 자료의 양 차이를 제품력 차이로 서술하지 않습니다.** 매 산출물에 명시.

컨설턴트 해석은 전부 `[가설]`로 표시하고, **선행조건과 반증 테스트**를 함께 답니다. 가설을 벤더 주장으로 세탁하지 않기 위한 장치입니다.

## 첫 실행 요약 (2026-09-16)

- **Workday 2026R2** production 2026-09-19 (D-3) / **SFSF 2H 2026** preview 2026-10-12, production 2026-11-13
- **2026-11-13에 SAP 리스크 3건이 겹칩니다** — 2H production + Legacy Home Page 삭제 + Legacy People Profile 구성 API 삭제
- **SF Recruiting → SmartRecruiters** 전환 경로 개시 (sunset 일자 없음, 전환 창 3~5년)
- 스킬 철학이 정반대 — Workday Skills Cloud는 *"유지보수 없이 ML이 채운다"*, SAP TIH는 *"AI 추론 스킬도 승인 절차를 거친다"*
- 한국 고객 활용안 8건 + **미확인 항목 11건**을 명시

## 알려진 제약

- 첫 실행 환경에서 egress 정책상 벤더 도메인 직접 열람(`WebFetch`)이 전부 차단되어, 모든 근거를 **검색 요약**으로 수집했습니다. 해당 라운드의 T1은 `T1*`로 강등 표기했습니다.
- 사용자의 실제 과거 대화 기록에는 접근할 수 없어, 한국 활용안의 고객 맥락은 워크스페이스에 영속화된 `cj-neo` 계열 스킬에서 **대용(proxy)**으로 도출했습니다. 산출물 §8에 명시되어 있습니다.

## HCM Release Atlas (대시보드)

2021–2026년 두 벤더의 릴리스 이력을 SKU·기능영역 축으로 정렬한 인터랙티브 대시보드.

```
data/hcm-timeline-2021-2026.json   # 마일스톤 56건 (vendor, wave, date, sku, EN, KO, tier, source)
data/insights-ko.json              # 도출 인사이트 7건 + 한국 HR Practice Benefit/Consideration 7개 테마
dashboard/template.html            # 템플릿 (데이터 주입 자리 표시자 포함)
dashboard/index.html               # 빌드 산출물 — 발행 대상
scripts/build-dashboard.js         # 데이터 주입 + 무결성 검사
```

갱신 절차 — **JSON만 고치고 다시 빌드**하면 페이지와 데이터가 어긋나지 않습니다.

```bash
node scripts/build-dashboard.js
```

빌드 스크립트는 다음을 검사하고, 하나라도 걸리면 **발행 대신 실패**합니다.

- 마일스톤 ID 중복
- 필수 필드 누락 (`v` · `wave` · `date` · `sku` · `tier` · `en` · `ko` · `src` · `srcName` · `label`)
- 정의되지 않은 SKU 키 / 벤더 코드
- 출처가 URL 형식이 아닌 항목
- 2021–2026 창을 벗어난 일자
- 인사이트의 `evidence`가 가리키는 마일스톤 부재

### 대시보드가 담은 것

| 섹션 | 내용 |
|---|---|
| 01 릴리스 리듬 | 12개 반기 축에 두 벤더의 production 시점 배치. **속이 찬 표식 = 일자 확인, 속이 빈 표식 = 반기만 확인** |
| 02 시점 × SKU 매트릭스 | 14개 기능영역 × 6년. 항목 클릭 시 영어 원문 · 한글 해설 · SKU · 출처 표시. 벤더·태그·키워드 필터 |
| 03 인사이트 | 6년 이력에서 도출한 7건. 각 인사이트의 `근거` 버튼이 해당 마일스톤을 매트릭스에서 열어줌 |
| 04 한국 HR Practice | 7개 테마별 Benefit / Consideration |
| 05 방법론과 한계 | 출처 등급, 문서 접근성 비대칭 고지, 수집 환경 제약, 남은 공백 5건 |

### 벤더 로고 · 커뮤니티 링크

두 벤더의 로고는 사용자가 제공한 아트워크를 **벡터로 다시 그려** `mark()`에 인라인 SVG로 넣었습니다(Workday: 블루 스퀘어 + 오렌지 아크 + 화이트 W / SAP SuccessFactors: 골드 하트 아웃라인). 브랜드 색은 `BRAND` 상수로 고정되어 테마가 바뀌어도 변하지 않습니다 — 로고는 아이덴티티이지 테마 토큰이 아니기 때문입니다.

이에 맞춰 **범주형 데이터 색 배정을 교환**했습니다. Workday 마크는 블루가 지배색, SuccessFactors 마크는 골드가 지배색이므로 `--wd`를 블루, `--sf`를 앰버로 바꿨습니다. 범례가 로고와 서로를 강화합니다. 색각·대비 검증은 교환 후에도 두 테마 모두 통과합니다.

SuccessFactors 마크는 선 드로잉이고 Workday 마크는 채워진 사각형이라 같은 박스 안에서도 크기가 달라 보였습니다. 하트에 흰색 플레이트를 깔아 두 마크가 동일한 면적으로 읽히게 했고, 마스트헤드의 두 타일은 `grid-template-columns:repeat(2,1fr)`로 동일 크기입니다.

각 타일은 해당 벤더의 **커뮤니티 진입점**을 겸합니다 — Workday Community(로그인) · Workday Docs(공개) / SAP Community(공개) · What's New Viewer(공개). 상단 고정 내비게이션에도 두 커뮤니티 링크를 두어 어느 위치에서든 닿습니다.

로고와 제품명은 각 사의 상표이며, 이 페이지는 두 벤더와 무관한 독립 분석 자료입니다 — 대시보드 §06에 명시했습니다.

### UI

오로라(aurora) 디자인 — 고정 메시 그라디언트 배경 위에 글래스 패널. 다크가 기본이고 라이트 변형도 같은 토큰 체계로 함께 정의되어 있습니다. 데이터 표면(매트릭스·sticky 헤더·드로어)만 `--panel` 토큰으로 불투명도를 올려, 배경 그라디언트가 수치와 텍스트를 침범하지 않게 했습니다.

매트릭스에서 항목을 선택하면 **매트릭스 우측에 드로어가 도킹**되며, 그리드 열이 0 → 430px로 늘어나는 동시에 패널 내용이 `clip-path`로 좌→우 와이프되어 열립니다. 1180px 미만에서는 매트릭스 아래로 스택됩니다. Esc로 닫히고, 드로어가 열릴 때 선택 항목이 가로 스크롤 밖으로 밀리지 않도록 재정렬합니다.

### 고객 상황 진단 (§03)

컨설턴트 교육용 섹션. 고객 상황을 입력하면 **데이터셋 안에서만** 근거를 찾아 제시합니다.

검색은 **결정적(deterministic)** 입니다 — 15개 기능영역 키워드 사전과 5개 상황 렌즈(폐기·벤더선정·비용·글로벌·국내법무)로 입력을 파싱하고, 마일스톤에 점수를 매겨 상위 8건을 출력합니다. 존재하지 않는 항목은 구조적으로 나올 수 없습니다.

- **매칭 하한**: SKU 영역이나 렌즈 태그에 걸리지 않은 항목은 단어가 2개 이상 겹쳐야 통과합니다. 우연한 한 단어로 엉뚱한 마일스톤이 올라오는 것을 막습니다.
- **매칭 근거 노출**: 어떤 단어가 어떤 영역에 걸렸는지 신호 칩으로 함께 보여줍니다 — 교육용이므로 결과보다 **판단 경로**가 중요합니다.
- **빈 결과를 그대로 보여줍니다**: 매칭이 없으면 "근거 없음"을 출력합니다. 억지로 채우지 않습니다.
- **AI 종합 소견** (`sample` capability): 매칭된 근거만 프롬프트에 담아 Claude가 진단·우선순위·리스크·확인질문을 작성합니다. "제공되지 않은 기능명·날짜·수치를 만들지 말 것, 근거에 없으면 미확인으로 표기할 것"을 지시합니다. 기능을 못 쓰는 뷰에서는 버튼 자체가 나타나지 않고, 나머지 결과는 그대로 동작합니다.

### 2026 이후 갱신

연도는 **어디에도 하드코딩되어 있지 않습니다.** 릴리스 웨이브가 `data/hcm-timeline-2021-2026.json`의 `releaseWaves`로 들어가 있고, 차트 축·연도 헤더·본문 문구·통계가 전부 여기서 파생됩니다. "오늘" 표식은 열람 시점에 계산되므로 2027년에 열어도 맞습니다.

다음 반기를 추가하려면:

1. `releaseWaves`에 웨이브를 추가합니다 (`precision`: `day` > `month` > `half`, 미발표 연도는 `planned: true`).
2. `milestones`에 항목을 추가합니다.
3. `node scripts/build-dashboard.js`

빌드는 **마일스톤의 연도에 해당 벤더의 웨이브가 없으면 실패**합니다 — 웨이브를 늘리지 않은 채 데이터만 추가하는 실수를 막습니다. 연도 상한은 `현재연도 + 2`로 열려 있습니다.

`planned: true` 웨이브는 차트에서 **예정 · 미발표** 구간으로 음영 처리되고 표식이 점선으로 바뀝니다. 두 벤더가 지켜 온 주기에서 도출한 예상이지 발표된 일자가 아니라는 점을 캡션에도 적었습니다.

### 인터랙션

| 기능 | 동작 |
|---|---|
| 딥링크 | 항목 선택 시 주소가 `#m=<id>`로 바뀌고, 그 주소로 열면 드로어가 복원됩니다. 드로어의 **링크 복사** 버튼 제공 |
| 드로어 이동 | **이전 / 다음** 버튼과 <kbd>←</kbd> <kbd>→</kbd> 키로 필터된 목록을 순회. 현재 위치를 `n / 전체`로 표시 |
| 내용 복사 | 드로어의 **내용 복사**가 마일스톤을 마크다운(출처 포함)으로 클립보드에 넣습니다 — 보고서·덱에 바로 붙일 수 있게 |
| 차트 필터 | 릴리스 표식을 클릭하면 해당 웨이브만 필터. 키보드 포커스와 Enter도 지원 |
| 필터 해제 | 활성 필터 수를 표시하는 **필터 해제 (n)** 칩 |
| 검색 단축키 | <kbd>/</kbd> 로 검색창 포커스, <kbd>Esc</kbd> 로 드로어 닫기 |
| 미리보기 | 매트릭스 칩에 마우스를 올리면 한글 해설 앞부분이 툴팁으로 표시 |
| 필터 기억 | 벤더·태그 선택을 `localStorage`에 보관 (try/catch로 감쌈, 없어도 정상 동작) |

### 데이터 규율

- **마일스톤 수는 벤더의 출시량이 아닙니다.** 두 벤더 모두 반기마다 250여 건을 내놓으며, 이 데이터셋은 구조·전략을 바꾼 변화만 선별 수록합니다. Workday 항목이 적은 것은 릴리스 노트가 Community 로그인 뒤에 있기 때문이며, 대시보드 §05에 이 점을 명시했습니다.
- 벤더 자체 주장 수치(예: Recruiting Agent의 70% · 55%)는 **주장치임을 본문에 표기**합니다.
- 출처가 충돌하는 값(예: ECP 지원 국가 수 50 / 53 / 60)은 **확정하지 않고 충돌 사실을 남깁니다**.
